# Morpheus Android Companion

First-pass native Android client for connecting a phone to a Morpheus app-server
that is already running on another machine. The app is a remote UI only: the
app-server owns thread runtime, tools, filesystem access, auth, and persistence.

## What Works

- Connects to `ws://...` or `wss://...` app-server endpoints with optional
  `Authorization: Bearer ...`.
- Scans typed Android connection QR payloads generated by Root Worker Settings
  and automatically fills the endpoint/token before connecting.
- Performs the app-server handshake: `initialize` request followed by the
  `initialized` notification.
- Lists recent threads with `thread/list`.
- Opens a selected thread with `thread/read` using `includeTurns: true`, then
  calls `thread/resume` with `excludeTurns: true` so live notifications stream
  into the selected conversation.
- Starts a new thread with `thread/start`.
- Sends text input with `turn/start`.
- Merges typed `thread/*`, `turn/*`, and `item/*` notifications into the same
  reducer used for read snapshots.

The renderer intentionally uses typed thread item `type` values from
app-server. Unknown future item types are displayed as compact JSON fallback
instead of parsing provider raw output or legacy assistant markers.

## Connect To Root Worker

The normal pairing path is through the Root Worker desktop app:

1. Start Root Worker. Its Electron process starts a single app-server runtime
   over stdio and also asks that same process to expose a capability-token
   protected WebSocket listener for mobile companions.
2. Open Root Worker Settings, find Android Companion, and scan the QR from the
   Android app's connection screen.
3. If connecting through a tunnel, expose the desktop app-server listener with
   your tunnel provider and replace the endpoint in Settings with the resulting
   `wss://...` URL before scanning. The token stays the same.

The QR connects Android to the same app-server process that the desktop client
is using. It does not start a second app-server, copy thread state, create a
tunnel, or change the WebSocket JSON-RPC protocol.

Root Worker's default mobile listener can be adjusted before launching the
desktop app:

- `ROOT_WORKER_MOBILE_LISTEN=ws://0.0.0.0:8910` controls the bind address.
- `ROOT_WORKER_MOBILE_ENDPOINT=wss://...` controls the endpoint shown in
  Settings, useful when a tunnel maps to the local listener.
- `ROOT_WORKER_MOBILE_LISTEN=off` disables automatic mobile listener setup.

If the mobile bind address is already in use, Root Worker keeps the desktop
stdio app-server connection running and shows the mobile listener as unavailable
in Settings.

If `APP_SERVER_CMD` or `CODEX_APP_SERVER_CMD` overrides the desktop app-server
launch command, Root Worker does not rewrite it. Include `--mobile-listen`,
`--ws-auth capability-token`, and `--ws-token-file` yourself if the custom
command should support Android pairing.

## Manual Server Development

For standalone Android development without the desktop app, build app-server
from the repository's Rust workspace:

```sh
rtk cargo build -p app-server --bin app-server
```

For local network access, bind app-server to an address reachable by the phone.
Non-loopback WebSocket listeners require auth:

```sh
rtk ./target/debug/app-server --listen ws://0.0.0.0:8910 --ws-auth capability-token --ws-token-file /absolute/path/to/ws-token.txt
```

Then enter `ws://<machine-lan-ip>:8910` in the Android app and paste the token
from `ws-token.txt`. This is a standalone development path and does not share
Root Worker desktop live runtime state unless it is the same app-server process
that the desktop client is using.

For tunnel access, expose that listener with your tunnel provider and enter the
resulting `wss://...` URL in the app. Keep WebSocket auth enabled for tunnel or
public network access.

Loopback-only development can run without WebSocket auth, but a phone cannot
usually reach `127.0.0.1` on the development machine:

```sh
rtk ./target/debug/app-server --listen ws://127.0.0.1:8910
```

## QR Payload

The recommended QR format is a typed, versioned JSON object:

```json
{
  "type": "morpheus.androidConnection",
  "version": 1,
  "endpoint": "wss://your-tunnel.example/root-worker",
  "token": "capability-token"
}
```

`token` is optional and is omitted when empty. `endpoint` must use `ws://` or
`wss://`; other schemes are rejected and do not trigger a connection. The
Android app also accepts `morpheus://connect?endpoint=...&token=...` and naked
`ws://` / `wss://` endpoints for compatibility, but Settings emits the JSON
payload above.

Treat the QR code like a bearer credential when it includes a token. Avoid
sharing screenshots, keep auth enabled for tunnel/public networks, and rotate
the token if it is exposed.

## Build The App

This directory is an independent Gradle Android project:

```sh
rtk gradle -p apps/android-companion testDebugUnitTest
rtk gradle -p apps/android-companion assembleDebug
```

If your environment does not have Gradle or the Android SDK installed, open
`apps/android-companion` in Android Studio and let it sync the project. The
core JSON-RPC and thread reducer logic lives outside Compose UI so it can be
covered by JVM unit tests.

## Scope Notes

This first version does not implement settings, file browsing/editing, approval
review UI, attachments, screenshots, or a tunnel service. It consumes the
existing app-server WebSocket JSON-RPC protocol directly and does not embed the
desktop Electron/Root Worker UI in a WebView.
