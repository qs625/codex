## Guardrails

- Dependency inversion：trait/DTO contract 放在 owner API crate 或 protocol-neutral crate；implementation crate 不得被 facade/re-export 间接拉回。
- 禁止伪拆分：不得复制或整体搬迁 `codex-core` / `codex-session-runtime` 大块实现到新 crate 后再“后续慢慢拆”；不得用 `session-tool-hosts` 这类新 host crate 替代 API trait 边界；不得在 session/runtime 内继续保留 tool/MCP/workflow/guardian/command 的 handler、host、adapter、router facade 或执行逻辑作为完成状态。
- Host 实现不是边界：`CoreToolDomainHost`、`CoreSessionToolRouter` 或任何 session-to-domain concrete host 只能是迁移中的未完成项。最终结构必须是 session/thread 消费 API trait object，domain implementation 和 tests 归 owner crate 或组合根，不能把 `Session` / `TurnContext` 当 IoC 容器传进 domain。
- session 依赖的全部 tool 能力必须抽象为 API trait/DTO；不得把 `Session` / `TurnContext` 包装成 `*ToolHost`、`*ToolRouter`、service registry 或其他 concrete host/facade 后交给 tool domain。tool implementation 归 tool owner crate，session/thread 只消费 contract，组合根负责装配注入。该规则优先于“先用 host 临时收口”的旧拆分写法；发现旧文档或代码继续引导 `CoreToolDomainHost` / `CoreSessionToolRouter` 时，先按本条修正。
- Session/thread 对外部 domain 的依赖必须先抽象为 API trait/DTO：turn loop 只能消费 tool execution、MCP access、workflow control、guardian approval、command runtime 等 capability contract；具体实现由 owner crate 或组合根注入，不能把 `Session` / `TurnContext` / `ThreadManager` 当跨 crate IoC 容器传给 domain implementation。
- `codex-core` 兼容层不计入 domain 完成；只有 implementation、测试和依赖门禁都迁到 owner crate，且 owner crate normal/dev graph 没有拉回不该依赖的 heavy runtime，才算完成。
- 同一 owner runtime 内部成员不需要 public API trait：`ThreadManager`、`AgentControl`、session/turn loop 在 `codex-session-runtime` 内部协作时保持 crate-private；只有 app-server、tool runtime、MCP adapter、workflow bridge 或其他外部 consumer 必须消费的能力，才进入 `codex-session-api` / `codex-thread-api`。
- 不使用 Rust `unsafe`；不为了拆分手写替代成熟第三方库。
- 测试代码也必须遵守依赖拓扑，不能通过 dev-dependency 间接拉回本应隔离的 heavy runtime。
