你正在为 my-codex 项目执行 CONTEXT CHECKPOINT COMPACTION。

输出一条供后续模型继续工作的 checkpoint message。不要输出寒暄、说明或泛泛的交接摘要。

checkpoint message 必须使用下面的 section 结构，并只保留与后续继续当前工作有关的信息。

## Current Goal
- 当前目标是什么。
- 如果当前没有 active work，明确写“当前没有新的主开发任务在推进”。
- 如果最近刚收口一个目标，写清楚它是什么、当前是否完成、是否还有后续收尾。

## Current Status
- 当前任务处于什么状态。
- 当前有哪些仍会影响后续继续工作的事实。
- 最近完成的关键结果及其意义。
- 仍需后续模型注意的状态差异、依赖关系或风险。

## Recent Progress
- 最近完成了什么，尤其是定位、实现、review、验证或决策。
- 关键决策与取舍。
- 已证伪的方向，避免下一轮重复试错。
- 重要命令及结果；只保留会影响后续判断的命令，不要贴长日志。

## Files Already Read
- 这是“文件阅读缓存”，目的是让后续模型能复用已经读过的有用信息，而不是为了同一点再次打开原文件。
- 按文件逐条记录：
  - 文件路径
  - 为什么读它
  - 关键结论
  - 后续真正会用到的具体内容：相关函数/类型/测试名、关键行为、契约、状态机语义、配置字段、错误信息、行文结论等。
  - 已经读过但不必完整重读的原因；如果仍需要重读，写明重读时只看哪些区域。
- 如果只有小部分内容有用，把这部分有用内容直接写进 checkpoint summary；后续通常不应为了这点局部信息重复打开整个文件。
- 如果文件大部分内容都对继续当前工作有用，或者后续实现/review 需要依赖完整上下文，可以写“建议重读”，但必须说明重读范围和原因。
- 如果文件只是用于确认事实、定位入口或排除某个方向，也放在这里记录结论；是否把对应方向列入 `Files Likely Safe To Skip` 另行判断。
- 不要只写“读过这个文件”，也不要把这个 section 写成简单的可跳过文件列表。

## Key Conclusions
- 汇总后续模型必须继承的当前任务结论。
- 区分已确认事实、当前假设和残余风险。
- 只保留会影响继续工作的结论。

## Files Likely Safe To Skip
- 这是“跳过清单”，用于列出大概率不值得继续投入的文件、模块、历史方向、方案或验证路径。
- 每条写清楚为什么可以跳过，避免下一轮重复探索。
- 不要在这里重复 `Files Already Read` 中的所有文件；只有当某个文件或方向整体上对后续推进不再有价值时，才放到这里。
- 如果某个文件只是“部分内容已缓存，后续通常不必为了同一点重读”，优先放在 `Files Already Read`，并在那里写清楚可复用内容。

## Current Blockers
- 当前硬 blocker、调度 blocker、验证 blocker。
- 如果没有 blocker，明确写“无硬 blocker”。
- 只记录与当前工作继续相关的阻塞。

## Next Steps
- 下一步具体做什么。
- 如果需要继续代码任务，写出优先文件、验证矩阵和禁止路径。
- 如果当前没有 active work，写出后续可能的切入点或维护建议。

写法要求：

- 保留后续继续工作真正需要的现场，不要压缩成几句概括。
- 明确记录哪些文件读过、为什么相关、得出了什么结论、是否还需要重读。
- 保留上一轮核心工作、关键验证、关键命令结论、证伪方向和后续依赖。
- 不要写大段代码、长日志或无结论的流水账。
- 如果某部分已经足够确认，可以明确写“通常不需要重读”及其原因。
